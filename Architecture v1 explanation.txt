### *PhenoPred Architecture v1 in Simple English*

Think of it like a factory assembly line for 1 DNA file at a time.

#### *1. The Big Idea: "Don't Assume, Detect"*
Your 2 files: AncestryDNA vs 23andMe are formatted differently. 
Old way: "Assume it's tab-separated"  
This architecture: "Read the file, figure out if it's tab or comma, figure out where the header is, then process it"

*Goal*: Never break if 23andMe changes format tomorrow.

#### *2. The Assembly Line - 10 steps for 1 file*
1. LOAD FILE → Just read raw lines. Don't touch data yet.
2. SPLIT COMMENTS → DNA files have lines starting with #. Separate them.
3. DETECT ENCODING → Is it UTF-8? ASCII? Figure it out.
4. DETECT DELIMITER → Is it TAB or COMMA?
5. FIND HEADER → Is the header row commented or not? What are column names?
6. PARSE ROWS → Split each line into columns: rsid, chromosome, position, genotype
7. RUN QUALITY CHECKS → Check: duplicate rsids? malformed rows? missing values?
8. RUN GENOMIC PROFILING → Count: How many chromosomes? What genotype format? Any indels?
9. BUILD REPORT → Put all findings into 1 clean "ProfilingReport" object
10. SAVE REPORT → Write that report to a JSON file
*Key rule*: Each step is independent. Step 7 doesn't care how step 4 worked.

#### *3. Folder Structure = Who does what job*
phenopred/
├── cli/           → The door. Where you type: phenopred upload file.txt
├── application/   → The manager. "Do step 1, then 2, then 3..."
├── domain/        → The brains. All the real logic. No file reading here.
│   ├── detection/     → Figures out format
│   ├── quality_checks/→ Finds problems in data
│   └── genomic_profiling/ → Describes the DNA notation
├── infrastructure/→ The hands. Actually reads files and writes reports.
└── tests/         → Proves everything works
*Why this matters*: If you want to change from JSON reports to PDF later, you only change `infrastructure`. The "brains" don't change.

#### *4. The Core Data Objects*
Claude is just defining boxes to hold info:
- `GenotypeFile`: "One DNA file you uploaded"
- `DataRow`: "One line: rs123 1 12345 A G"
- `Finding`: "We found 12 duplicate rsids"
- `Profile`: "This file uses 2-column genotype format"
- `ProfilingReport`: "Final summary of everything we found"

No "eye color" or "avatar" here yet. That's future.

#### *5. 3 Important Rules Claude baked in*
1.  *Per-file only*: It will NOT compare Ancestry vs 23andMe yet. That’s "future work". v1 does 1 file.
2.  *No Biology*: It will NOT say "this SNP means blue eyes". It only says "this file has 614,000 SNPs in format X"
3.  *Sensitive Data*: It will NOT log your actual DNA `A G` to files. Only counts.
